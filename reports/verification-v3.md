# 변경된 17개 검토 지시 검증

검증일: 2026-09-21. 실제 계약서 대신 저장소의 가상 NDA만 사용했다.

## 반영 내용

- 현재 지시 파일을 `prompts/nda-review-system.md`로 통일하고 매 검토 요청에서 읽는다.
- 목적의 적정성과 자유 입력란, 한국어·영어 입력 해석 및 반영 상태를 표시한다.
- 새 1~17번 체계를 적용하고, 17번은 문제없는 기타 조항도 모두 요약한다.
- 누락된 필수 조항은 진단에 그치지 않고 수정 문구가 있는지 검증한다.
- 준거법·분쟁해결의 Note를 분리하고 상대방 약칭·중립성 취지·한 문장 형식을 서버에서 생성한다.
- 원문 ID로 수정 위치를 고정하고, 동일 문구의 중복 수정은 병합한다. 서로 다른 수정의 충돌은 오류로 알린다.
- 식별 가능한 수동 조항번호가 생략되면 보존하며, 번호가 달라지면 자동 보정 대상으로 처리한다.
- 오류에 단계·검토 항목·문단 위치·원인·해결 방법을 표시한다.

## 결과

자동 테스트 25개가 통과했다. API 흐름, 4단계 DOM 동작, 선택 권고, 추적 변경, 원문 보존, Note 조건, 오류 표시 등을 검증했다.

실제 API에는 한국 회사가 수령자이고 싱가포르 회사가 공개자인 가상 일방 NDA를 전송했다. 한국어와 영어로 목적·준거법·ICC 중재·기간을 각각 지정해 다음 결과를 확인했다.

| 입력 | 검토 항목 | 기본 변경 | 개별 Note | 기타 조항 요약 | 채택한 추가 권고 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 한국어 | 17 | 12 | 2 | 4 | 1 |
| 영어 | 17 | 15 | 2 | 4 | 1 |

모델은 `gpt-5.4-mini`를 유지했다. 사실 추출은 low, 수정안 작성은 medium 추론 설정을 사용했다. 두 입력에 대한 생성 문구는 동일하지 않으며, 법률적 동등성까지 자동 증명한 것은 아니다.

마지막 조항번호·Note 처리 변경은 저장해 둔 실제 API 응답을 다시 처리하여 검증했다. 이 재처리에는 추가 API 호출을 사용하지 않았다. 최종 생성 파일을 설치된 Microsoft Word에서 직접 열어 다음 네 가지 동작을 각 입력별로 확인했다.

| 입력 | V1 변경 수 | V2 변경 수 | 모든 변경 수락 | 모든 변경 거절 |
| --- | ---: | ---: | --- | --- |
| 한국어 | 160 | 185 | 의도한 수정 텍스트와 일치 | 원문과 일치 |
| 영어 | 180 | 195 | 의도한 수정 텍스트와 일치 | 원문과 일치 |

기존에 사용자가 열어둔 Word 문서는 건드리지 않고 별도 숨김 인스턴스를 사용했다. 검증용 문서·원시 응답은 Git 제외 경로 `.runtime/live-verification`에 있다. API 키도 Git 제외 상태다.

## 범위

브라우저 화면은 DOM 테스트로 확인했으며 이번 환경에서 실제 브라우저의 시각 검증은 수행하지 못했다. 가상 계약에 대한 기능 검증이며 모든 계약의 법률적 정확성, 복잡한 문서 서식 또는 최신 market practice를 보증하는 결과는 아니다. 실시간 법률 검색은 구현하지 않았다.

로컬 서버 상태에서 API 연결, Microsoft Word 변환기, 지시 버전 v3를 확인했다. 접속 주소는 `http://localhost:4173`이다.
