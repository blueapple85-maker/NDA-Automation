# NDA Studio

비밀유지계약(NDA)을 업로드하고, 대리하는 회사의 입장에서 17개 항목을 검토하는 로컬 웹사이트입니다. HTML/CSS/JavaScript 화면과 Node.js 서버로 구성됩니다.

## 실행

이 컴퓨터에서는 **`start.cmd`를 실행하고 <http://localhost:4173>에 접속**하세요. 설치된 Node.js가 없으면 상위 `.tools` 폴더의 휴대용 Node.js를 사용합니다.

다른 컴퓨터에서는 Node.js 22 이상을 설치한 후:

```sh
npm ci
npm start
```

`index.html`을 직접 열면 화면을 확인할 수 있지만, 문서 처리·데모·다운로드 기능에는 로컬 서버가 필요합니다. 프런트엔드의 외부 CDN·폰트 의존성은 없습니다.

화면은 딥 그린 사이드바와 오프화이트 배경의 반응형 워크스페이스입니다. 사이드바에서 진행한 단계로 돌아갈 수 있고, 검토 기준을 바꾸면 이전 결과 대신 재생성을 안내합니다. 추가 권고사항의 전체 채택·선택 해제를 지원하며, 최종 화면에서 반영·미반영 항목과 생성 시각을 확인할 수 있습니다. `검토 가이드`에서 네 단계의 사용법을 볼 수 있습니다.

## 속도 최적화

- 같은 검토 건에서 회사·입력 조건·모델·추론 강도·검토 지침이 동일하면 마지막으로 완료한 결과와 V1을 재사용합니다. 화면에 `동일 조건의 이전 결과`로 표시하며, 추가 AI 요청이 없습니다. 하나라도 바뀌면 새로 검토합니다. 실패·미완료 결과와 다른 업로드 건의 결과는 재사용하지 않습니다.
- 추가 채택 없이 최종본을 만들면 V1의 검증된 문서 내용을 그대로 사용합니다. 같은 권고 선택으로 다시 최종본을 요청하면 이미 만든 파일을 재사용하고, 선택이 달라지면 다시 반영합니다.
- 입력 해석·17개 체크리스트·수정 전후 비교는 상세 패널을 처음 펼칠 때 화면에 구성합니다. 요약·다운로드·기타 조항과 채택할 권고는 바로 표시하며, 닫았다 다시 열 때는 상세 내용을 다시 그리지 않습니다.
- HTML/CSS/JavaScript를 gzip으로 압축해 전송하고 ETag로 변경 여부를 확인합니다. 변경되지 않은 화면 파일은 본문 재전송 없이 304로 응답합니다. 소스 파일을 수정하면 새 ETag를 적용합니다. 계약서·AI 결과 API·다운로드 파일에는 계속 `no-store`를 적용합니다.
- AI 출력 중 1~16번의 중복 설명을 줄입니다. 화면에서 사용하지 않는 내부 목록의 title/summary/impact만 비워 반환하도록 하며, 17개 검토 결과·원문 인용·모든 본문 문단 분류·실제 수정 문구·17번 기타 조항 요약은 유지합니다. 모델과 추론 강도는 변경하지 않습니다. 요청·출력량을 줄이는 방식은 [OpenAI 지연 최적화 지침](https://developers.openai.com/api/docs/guides/latency-optimization)을 참고했습니다.

재사용 결과도 기존과 같은 메모리 보관 기간을 따르며, 검토 삭제·만료·서버 종료 시 함께 제거됩니다. 새 계약의 최초 AI 검토 시간은 문서 길이와 API 응답에 따라 달라집니다.

## 실제 AI 검토 연결

1. `NDA-Automation` 바로 위 폴더의 `key.txt`에 API 키 하나를 한 줄로 저장합니다. 현재 위치는 `C:\Users\bluea\Desktop\해커톤\key.txt`입니다. Windows에서는 `Key.txt`도 같은 파일로 인식합니다.
2. `start.cmd`로 서버를 다시 실행합니다. 실행 위치와 관계없이 프로젝트를 기준으로 키 파일을 찾습니다.
3. 서버는 이 파일의 값을 `.env`의 기존 키보다 우선 사용합니다. 키를 바꾼 경우 서버를 다시 실행하세요.

다른 키 파일을 사용하려면 `.env`의 `OPENAI_API_KEY_FILE`에 절대 경로 또는 프로젝트 기준 상대 경로를 지정합니다. 기본 `key.txt`가 없는 경우에만 `OPENAI_API_KEY` 환경변수를 대신 사용합니다. 지정한 키 파일을 읽지 못하거나 비어 있으면 다른 키로 조용히 전환하지 않고 오류를 안내합니다. UTF-8 BOM과 앞뒤 공백·줄바꿈은 제거하며, 키 한 줄 또는 `OPENAI_API_KEY=...` 한 줄을 지원합니다. 파일의 키는 서버 메모리에서만 사용하고 `.env`에 복사하지 않습니다.

키는 서버에서만 사용되며 브라우저로 반환하거나 저장소에 커밋하지 않습니다. 기본 모델은 `gpt-5.4-mini`이고 `OPENAI_MODEL` / `OPENAI_REVIEW_MODEL`로 변경할 수 있습니다. API 사용 비용은 연결한 계정에 발생합니다. 키가 없거나 오류가 발생하면 명시적으로 안내하며, 실제 문서에 가상의 분석 결과를 반환하지 않습니다.

GPT-5.4 계열로 수정안을 작성할 때는 `OPENAI_REVIEW_REASONING=medium`을 기본으로 사용하며, 초기 정보 추출에는 `low`를 사용합니다. 추론을 사용하지 않을 때보다 처리 시간과 API 비용이 늘어날 수 있습니다. [모델의 지원 설정](https://developers.openai.com/api/docs/models/gpt-5.4-mini)을 참고하세요.

법률검토의 기본 출력 한도는 **32,000토큰**입니다. 출력 길이로 중단되면 **64,000토큰으로 한 번 자동 재시도**합니다. 이 한도는 화면에 보이는 결과뿐 아니라 추론 토큰도 포함합니다([공식 설명](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning)). 잘린 결과를 이어 붙이거나 수정본으로 사용하지 않고, 같은 문서와 조건으로 완전한 결과를 다시 요청합니다. 추론 수준과 17개 검토 범위는 유지합니다. 실제 생성량에 따른 API 비용과 재시도 시간이 추가될 수 있습니다.

필요하면 `.env`에 `OPENAI_REVIEW_MAX_OUTPUT_TOKENS=32000`, `OPENAI_REVIEW_RETRY_MAX_OUTPUT_TOKENS=64000`을 설정하고 서버를 다시 실행하세요. 초기 정보 추출은 `OPENAI_ANALYZE_MAX_OUTPUT_TOKENS=9000`, `OPENAI_ANALYZE_RETRY_MAX_OUTPUT_TOKENS=18000`입니다. 환경변수가 없으면 이 기본값을 사용하며, 최초 한도만 바꾸면 재시도 한도는 그 두 배(최대 128,000)입니다. 재시도 한도는 최초 한도 이상이어야 하며, 둘을 같게 설정하면 길이 초과 자동 재시도를 끕니다. 앱은 1~128,000의 정수만 허용하지만, 다른 모델로 변경할 때는 그 모델의 최대 출력 한도 이내로 두 값을 지정해야 합니다.

**예시 계약 체험**은 API 키 없이 사용할 수 있습니다. 가상의 한국·싱가포르 회사 간 NDA와 고정된 시연 규칙을 사용하며, 모든 화면과 문서 제목에 데모임을 표시합니다. 데모의 자유 입력은 문구 해석 없이 그대로 삽입하므로 실제 AI 검토와 구별됩니다.

## 네 단계

1. **업로드:** `.docx`, `.doc`, 최대 10MB. 원본 파일을 별도로 보관합니다.
2. **검토 기준:** 당사자·설립국, 사용 목적과 적정성, 상호/일방/비대칭 여부, 준거법·분쟁해결·계약기간·존속기간을 확인합니다. 대리 회사 하나를 선택하고, 사용 목적과 네 조건의 대체 내용을 한국어 또는 영어로 입력합니다. 빈칸은 원문을 유지합니다.
3. **1차 수정본:** 1~16번 기본 검토와 13번 준거법·14번 분쟁해결의 개별 Note를 실제 Word 변경내용 추적으로 반영합니다. 입력 해석과 반영 상태를 표시합니다. 17번은 특이사항 없는 기타 조항까지 모두 요약하고, 문제가 있는 항목에는 선택 권고를 제시합니다. 기본 선택은 보류입니다.
4. **최종 수정본:** 기본 수정에 채택한 권고만 합쳐 V2를 만듭니다. 업로드 원본, 검토 기준 사본, V1, V2를 각각 다운로드할 수 있습니다. 미채택·보류 권고는 반영하지 않습니다.

현재 검토 지시는 [prompts/nda-review-system.md](prompts/nda-review-system.md)입니다. **서버가 매 검토 요청마다 이 파일을 읽으므로 다음 검토부터 수정 내용이 적용됩니다.** 웹사이트 제작 지시는 [prompts/nda-website-build.md](prompts/nda-website-build.md)에 있습니다. 이전 프롬프트는 `prompts/nda-review-system.previous.md`, 이전 화면은 `index.previous.html`에 보관했습니다. 이전 `assets/review-prompt.js` 번들은 현재 앱에서 사용하지 않습니다.

## DOC 변환

Windows에서는 설치된 **Microsoft Word**로 `.doc`를 `.docx`로 변환합니다. Word COM 실행이 가능한 사용자 세션에서 `start.cmd`를 실행하세요. 또는 LibreOffice의 실행 파일 경로를 `.env`의 `SOFFICE_PATH`에 지정할 수 있습니다. 변환기는 매크로와 링크 갱신을 비활성화한 별도 Word 인스턴스를 사용합니다.

변환기가 없거나 변환에 실패하면 DOCX 저장 후 재업로드 안내를 표시합니다. DOC 확장자만 허용하고 내용은 읽지 못하는 가상 업로드 기능이 아닙니다. 암호화·손상된 파일과 RTF/HTML을 `.doc`로 이름만 바꾼 파일은 지원하지 않습니다.

## 변경내용 추적과 검토 범위

- DOCX 내부에 `w:ins`, `w:del`, 삭제 텍스트, 작성자, 작성 시각, 변경 ID를 기록합니다. Word의 실제 수락·거절 대상입니다.
- 기존 문서 패키지를 기반으로 지정한 문단만 편집하며, 수정 대상의 정확한 전체 원문과 문단 ID를 검증합니다. 변경 없는 문서 구성요소와 표·단락·글자 서식을 가능한 범위에서 유지합니다.
- 표 안의 단순 문단은 수정할 수 있습니다. 필드·하이퍼링크·복잡한 개체가 섞인 문단은 자동 대체하지 않습니다. 머리말·꼬리말·각주·미주·주석은 분석 참고자료로 전달하며 자동 수정은 본문 문단에 한정합니다.
- 기존의 단순 삽입·삭제·이동 이력은 수락한 사본으로 기준을 만들며, 사용자가 이 처리를 확인해야 수정본을 생성합니다. 원본 이력은 업로드 원본에 유지됩니다. 기존 구조·서식 변경 이력은 Word에서 정리한 사본이 필요합니다.
- 페이지 번호나 자동 번호를 추정하지 않습니다. 조항번호를 확정할 수 없으면 문단 ID로 표시합니다. 이미지 OCR과 삽입 개체·매크로 문서는 지원하지 않습니다.
- V2는 항상 같은 검토 기준 사본에서 누적 생성합니다. 동일 문단을 대체하는 수정끼리 충돌하면 생성 오류를 표시하고 임의로 덮어쓰지 않습니다. 권고사항은 하나씩 채택하거나 Word에서 수동 병합할 수 있습니다.
- 무기한 존속 조항에 대체 입력이 없으면 원문을 유지하고 유한한 기간·기산점을 확인사항으로 남깁니다. 확인사항이 남은 결과는 초안입니다.
- 한국법이 아닌 법은 13번, KCAB가 아닌 분쟁해결은 14번 Note를 **각각 한 문장**씩 삽입합니다. 형식은 `[Note to 상대방약칭: 이유]`이며 대리 회사를 바꾸면 수신 상대방도 바뀝니다. 설립국·실제 조건과 어긋나게 중립성을 단정하지 않습니다. 기타 수정 이유는 화면에 표시합니다.
- AI가 원문 전체를 다시 작성하도록 요구하지 않고 고정된 문단 ID로 수정 위치를 지정하게 합니다. 서버가 original을 가져와 정확한 위치에 수정합니다. 모든 본문 문단의 분류와 기타 조항 요약 누락 여부를 검증합니다.
- 식별 가능한 수동 조항번호가 수정 문구에서 생략되면 원래 번호를 붙이고, 다른 번호로 바뀌면 오류로 처리합니다. Note의 명분은 서버가 계약 언어의 표준 한 문장으로 작성하여 중립성 취지가 누락되거나 상대방의 합의를 기정사실화하지 않게 합니다.

## 문제 해결

실패 시 화면에 **단계·문제 내용·검토 번호·문단 위치·해결 방법·오류 코드**를 표시합니다. 해당되는 경우 제공자의 요청 ID도 표시합니다. API 키나 제공자의 원문 오류 응답은 노출하지 않습니다.

### JSONL 실행 로그

`start.cmd` 또는 `npm start`로 서버를 실행하면 `logs/nda-studio-YYYY-MM-DD.jsonl`에 이벤트별 JSON 한 줄을 추가합니다. 파일 날짜와 `timestamp`는 UTC 기준입니다. 날짜가 바뀌면 새 파일을 만들며, 서버 재시작 시 기존 파일에 이어 씁니다. 이전 실행의 로그를 소급해서 생성하지는 않습니다.

기록 내용은 다음과 같습니다.

- `server.started` / `server.stopped`: 서버 시작 또는 정상적인 서버 닫기. 강제 종료 시 종료 이벤트가 없을 수 있습니다.
- `request.completed` / `request.aborted`: 분석·검토·최종본·다운로드·삭제 등 API 처리 결과, `durationMs`, HTTP 상태, 결과 재사용 여부(`cacheHit`), 문단·수정·채택 개수.
- `ai.request` / `ai.response` / `ai.error`: 모델, 추론 강도, 호출 차수, 출력 한도, 처리 시간, OpenAI 요청 ID, 제공된 입력·출력·캐시 입력·추론 토큰 수. 추론 토큰은 출력 토큰에 포함됩니다.
- `ai.retry` / `ai.validation_failed`: 출력 한도 확장 또는 원문 인용·결과 형식 보정, 오류 코드, 해당 문단 ID.

같은 HTTP 작업은 `traceId`, 같은 업로드 건은 `caseId`로 연결합니다. 응답 헤더의 `X-NDA-Trace-ID`는 로그의 `traceId`와 같습니다. OpenAI의 `requestId`는 별도 필드입니다. 데모 실행은 `demo:true`로 구분하며 실제 AI 토큰 사용을 만들어 기록하지 않습니다.

API 키·인증 헤더·파일명·회사명·계약서 원문·사용자 입력·프롬프트·AI 수정 문구·원문 인용·오류의 원문 메시지는 저장하지 않습니다. 허용한 운영 메타데이터만 기록하며, 로그는 웹 경로로 제공하지 않고 Git에서도 제외합니다. 쓰기는 비동기로 순서대로 처리하여 검토 요청이 디스크 저장을 기다리지 않게 합니다. 쓰기 실패 시 서버 콘솔에 경고를 표시하며 `/api/status`의 `logging.healthy`와 `logging.errorCode`로 확인할 수 있습니다.

로그는 검토 건의 2시간 만료와 별도로 디스크에 남으며 자동 삭제하지 않습니다. 필요 없는 날짜의 로그 파일은 직접 삭제할 수 있습니다. Node 모듈을 직접 사용하는 테스트 서버는 기본적으로 기록하지 않으며, `createServer({logger})`로 주입한 로거만 사용합니다.

프로젝트 폴더에서 현재 날짜의 로그를 실시간으로 보려면 PowerShell에서 다음을 실행합니다.

```powershell
$ndaLogDate = (Get-Date).ToUniversalTime().ToString('yyyy-MM-dd')
Get-Content -LiteralPath ".\logs\nda-studio-$ndaLogDate.jsonl" -Encoding UTF8 -Tail 20 -Wait
```

UTC 날짜가 바뀌면 명령을 다시 실행해 새 파일을 확인하세요. JSONL 한 줄은 예를 들어 `{"timestamp":"2026-09-22T01:00:00.000Z","event":"ai.retry","stage":"review","retryReason":"output_limit","previousMaxOutputTokens":32000,"maxOutputTokens":64000}` 형태입니다.

| 코드 | 의미 / 조치 |
| --- | --- |
| `API_KEY_MISSING`, `AI_HTTP_401` | 키 미설정 또는 인증 실패: 서버 설정 확인 |
| `AI_HTTP_429` | 크레딧·예산 부족과 요청량 제한을 구분하여 안내 |
| `AI_INCOMPLETE` | 출력 길이 초과는 한도 확장 후 한 번 자동 재시도. 다시 실패하면 적용 한도·제공된 생성/추론 토큰 수·마지막 요청 ID 표시: `.env`의 출력 한도 조정 또는 문서 분할 |
| `AI_OUTPUT_CONFIG` | 출력 한도가 유효한 정수가 아니거나 재시도 한도가 최초 한도보다 작음: 안내된 환경변수 수정 후 서버 재시작 |
| `AI_TIMEOUT` | API 요청 한 번의 응답이 300초를 초과함: 연결 상태·문서 길이 확인 |
| `SOURCE_QUOTE_MISMATCH`, `EDIT_ANCHOR` | 원문 인용·수정 위치가 불일치: 해당 문단 확인 |
| `OTHER_SUMMARY_MISSING`, `COVERAGE_MISSING` | 기타 조항 요약 또는 본문 문단 누락 |
| `NOTE_FORMAT`, `NOTE_REQUIRED` | 개별 Note의 약칭·형식·누락 문제 |
| `REVISION_CONFLICT` | 동일 문단의 수정 충돌: 해당 권고를 보류하거나 Word에서 병합 |

AI 결과의 형식·위치·누락 검증 오류는 구체적인 실패 사유를 전달하여 **최대 한 번 자동 보정**합니다. 여전히 실패하면 근거 없는 수정본을 생성하지 않고 문제를 표시합니다. 자동 보정은 추가 API 요청을 사용할 수 있습니다.

출력 한도 확장은 이 자동 보정과 별개로 분석/검토 작업마다 최대 한 번만 허용합니다. 확장한 한도는 보정 요청에도 유지하므로, 두 종류의 재시도가 모두 필요한 작업도 최대 3회 API 요청으로 종료합니다. 인증 실패·크레딧 부족·생성 거절에는 출력 한도 확장 재시도를 하지 않습니다.

AI는 계약 문구를 분석하지만 법률·사실 오류가 있을 수 있습니다. 최종 법률 판단과 문구, Word 서식, 자동 번호·교차참조는 체결 전에 확인하세요. 실시간 법령·판례·market practice 검색은 수행하지 않습니다.

## 데이터 처리

로컬 서버는 `127.0.0.1`에만 연결됩니다. 원본·추출 문단·분석 결과·수정본은 2시간 후 만료되며, 메모리 정리는 1분 간격으로 실행됩니다. 서버 종료 시에도 사라집니다. 최종 화면에서 즉시 삭제할 수도 있습니다. DOC 변환용 `.runtime` 임시 파일은 변환 후 삭제합니다. 비정상 종료 시 남은 임시 파일 중 2시간이 지난 것은 다음 서버 실행 때 정리합니다.

실제 분석·검토 시 문서 텍스트와 사용자 조건을 OpenAI API로 전송합니다. 파일 자체나 브라우저의 다른 파일은 전송하지 않습니다. Responses API의 `store:false`를 사용하며 제공자의 별도 데이터 처리 정책은 적용됩니다. 문서를 인터넷 검색에 전송하지 않고, 계약 내용을 서버 로그에 기록하지 않습니다.

동일 PC에서 쓰는 단일 사용자 도구입니다. 인터넷 배포용 인증·사용자별 권한·지속 저장은 포함하지 않습니다.

## 인용 오류 처리

`SOURCE_QUOTE_MISMATCH`는 AI의 인용이 지정한 원문 문단과 일치하지 않는다는 뜻이며 API 키 오류가 아닙니다. 공백·탭·줄바꿈·일반/비분리 공백·직선/곡선 따옴표 등 한정된 표기 차이는 해당 원문의 정확한 부분 문자열로 복원합니다. 단어, 부정어, 숫자, 대소문자, 조항 위치를 임의로 바꾸거나 요약문을 원문으로 인정하지 않습니다. 실제 불일치는 모두 모아 원문과 함께 한 번 자동 재검토하며, 실패하면 오류 화면에서 원문과 AI 인용을 비교할 수 있습니다. 원본 계약서를 오류에 맞춰 수정할 필요는 없습니다.

## 검증

```sh
npm test
```

문서 수정 수락·거절의 텍스트 결과, 선택한 권고만 반영되는 V2, 중복·원문 불일치·조건 변경 차단, API 오류·자료 삭제, 4단계 DOM 화면 흐름을 검증합니다. AI 호출 테스트의 주입 서비스는 테스트 서버에서만 사용되며 운영 서버에 테스트 응답 경로는 없습니다.

Windows Word가 있으면 실제 Word 검증도 실행할 수 있습니다. 가상 계약만 사용합니다.

```powershell
node scripts/prepare-verification.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify-word.ps1 -FixtureDirectory "$PWD\.runtime\verification"
```

실제 API를 이용하는 별도 검증은 아래와 같습니다. 가상의 일방 NDA만 전송하여 한글·영문 입력, 필수 조항 신설, 독립적인 두 Note, 기타 조항 전체 요약과 채택 후 V2를 검증합니다. API 사용료가 발생하며 결과는 Git 제외 경로 `.runtime/live-verification`에 저장합니다.

```sh
node --env-file=.env scripts/verify-live.cjs --run-live
```

이미 저장된 가상 API 응답으로 서버 처리와 문서 생성만 재검증하려면 `node scripts/verify-live.cjs --replay`를 사용합니다. 추가 API 호출은 발생하지 않습니다. 이번 변경의 실제 검증 결과는 [reports/verification-v3.md](reports/verification-v3.md)에 있습니다.
