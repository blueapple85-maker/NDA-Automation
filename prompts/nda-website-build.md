# NDA 법률 자동검토 웹사이트 제작 프롬프트

심플하고 시크한 한국어 NDA 법률 자동검토 웹사이트를 HTML/CSS/JavaScript로 구현하라. 밝은 배경, 차콜 텍스트, 절제된 녹색 포인트, 충분한 여백을 사용하고 모바일·키보드 접근을 지원하라. 아래 기능을 실제 작동하게 구현하고, AI 미연결 상태를 가짜 결과로 숨기지 말라.

## 1. 문서 업로드

첫 화면에서 DOCX·DOC 파일을 선택하거나 드래그하여 업로드한다. 실제 파일 형식을 검사하고 DOC는 변환기를 통해 DOCX로 변환한다. 원본은 별도로 유지한다. 처리 상태와 구체적 실패 이유를 표시한다. API 키는 서버에서만 관리한다. 예시 체험은 가상의 계약임을 화면과 산출물에 명시한다.

## 2. 핵심정보와 사용자 입력

빠르게 분석해 다음을 원문 근거와 함께 표시한다.

1. 각 당사자의 이름과 jurisdiction of incorporation. 주소로 설립국을 추정하지 않는다. 옆에서 대리 회사 하나를 선택한다.
2. 비밀정보 사용 목적과 적정성 판단. 옆에 빈 대체 목적 입력란을 둔다.
3. 상호/일방 여부와 실제 공개자·수령자. 비대칭·불명확하면 그대로 설명한다.
4. 준거법과 빈 대체 입력란.
5. 분쟁해결 방식과 빈 대체 입력란.
6. 계약기간·존속기간을 각각 표시하고 각각 빈 대체 입력란을 둔다.

사용자가 한국어·영어·혼용으로 입력해도 의미를 이해하고 계약 언어로 수정한다. 대체 입력이 없으면 원문을 유지한다. 판단에 필요한 사실이 없으면 임의로 보완하지 않고 구체적으로 확인한다.

## 3. 1차 수정본과 17개 항목 검토

아래 번호를 변경하지 않는다. 구체적인 검토 방식은 [nda-review-system.md](nda-review-system.md)를 적용한다.

1. 계약당사자 정의.
2. 사용된 Affiliate 정의.
3. 비밀정보 정의. 우리 회사가 수령자이면 합리적 market practice 범위에서 좁힌다.
4. 사용 목적과 사용자 대체 내용.
5. reasonable care·목적 내 사용·need to know.
6. 관계자의 위반에 해당 당사자가 책임지는 문구. 없으면 추가.
7. 공개정보·기지 정보·적법한 제3자 제공·독립 개발의 네 예외. 없으면 추가.
8. 강제 공개.
9. 계약기간·유한 존속기간 및 기산점, 사용자 입력.
10. 비밀정보·IP 소유권 이전 없음. 없으면 추가.
11. 정확성·완전성 등 보증 부인. 없으면 추가.
12. 과도하지 않은 반환·폐기. 없으면 추가.
13. 준거법 및 사용자 입력. 한국법이 아니면 중립적 법을 지향하는 한 문장 Note를 삽입.
14. 분쟁해결 및 사용자 입력. KCAB가 아니면 중립적 기관/포럼을 지향하는 한 문장 Note를 삽입.
15. Publicity.
16. 추가 계약 체결 의무 없음의 조항이 있다면 적정성 검토.
17. 기타 모든 실질적 조항을 축약하여 표시. 특이사항 없는 일반 조항도 포함.

13번과 14번의 메모는 `[Note to 상대방약칭: 한 문장의 이유]` 형식으로 **각각 본문에 실제 변경내용 추적 삽입**한다. 동일 문단에 준거법과 분쟁해결이 함께 있어도 합치지 않는다. 선택한 법·기관이 일방의 자국 것이면 중립적이라고 허위로 설명하지 않고, 중립적 선택을 지향한다는 취지와 현재 선택의 확인 필요를 표현한다.

1~16번의 수정은 V1 DOCX에 적용한다. 17번의 특이사항은 (a) 축약 내용·영향, (b) 조항번호·근거, (c) 우리 회사에 유리한 권장 문구를 표시하고 채택·미채택·보류를 선택하게 한다. 초기 선택은 보류다. 사용자 입력의 해석과 반영 상태도 표시한다.

## 4. 최종본

같은 원본 기준으로 V1의 기본 수정과 채택된 17번 권고만 누적하여 V2 DOCX를 생성한다. 미채택·보류는 넣지 않는다. 원본·검토 기준 사본·V1·V2를 다운로드할 수 있게 한다. Word에서 수락·거절할 수 있는 실제 삽입·삭제 변경 이력, 작성자·시각·ID를 생성한다. 서식·표·기존 문서 구성요소를 보존하고 같은 문단의 충돌은 임의로 덮어쓰지 않는다. 기존 변경 이력이 있는 문서의 검토 기준을 명시하고 사용자 확인을 받는다.

## 신뢰성과 문제 해결

원문 ID·인용·17개 체크리스트·전체 본문 검토 범위·기타 조항 누락·Note 조건과 상대방 약칭을 검증한다. 원문 전체를 AI가 재출력하게 하지 않고 검증된 ID에서 가져온다. 오류는 단계, 해당 검토 번호/조항/문단, 구체적인 원인, 사용자가 취할 해결 방법을 알려준다. API 인증 실패·예산 부족·요청량 제한·출력 길이 한도·응답 지연을 구분한다. 키·민감한 서버 응답은 노출하지 않는다. 해결할 수 없는 문단은 완료로 가장하지 않는다.

완료 전 가상의 상호·일방 NDA로 실제 업로드와 Word 추적 변경을 검증하고, 한국어·영어의 같은 입력 의미가 같은 계약 조건으로 반영되는지 확인하라.
